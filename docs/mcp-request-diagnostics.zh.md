# 短时全量 MCP 捕获（准备模式）

用途是记录协调重试时是否出现了目标形状的 MCP HTTP 请求及响应头终态。此方案不再采样，也不因正常响应使用失败预算。没有记录只能说明观察范围内未见请求；错误主机、其他路径、代理前置失败、日志输出失败等不能据此归因为 Today 网络错误。

## 默认关闭与范围

普通构建默认关闭；旧的单独 `__AGENTPARTY_MCP_DIAGNOSTICS_UNTIL__` 也不会开启。必须显式同时给出 `__AGENTPARTY_MCP_DIAGNOSTICS_FROM__` 和 `__AGENTPARTY_MCP_DIAGNOSTICS_UNTIL__`，都是绝对 UTC 时间，开始早于截止且间隔不超过十分钟。不读取新秘密、不增加管理 API/凭据、不写系统或网络配置。时间与状态仅在请求 I/O 上下文初始化，避免 workerd 模块求值时的零时钟。

匹配 `/api/channels/<单个路径段>/mcp` 及可选末尾斜杠，包括实际路由可能拒绝的错误群路径段；只输出固定模板 `/api/channels/:slug/mcp`。不改变真实路由、认证、Origin 或权限。不记录 OAuth discovery、其他 API、正文、RPC 参数、IP、Token/hash、Cookie、查询参数、实际群/身份或客户端 request-id。

## 八字段和状态

固定前缀 `mcp_request_diagnostic` 后只有八字段：`request_time`、服务端随机 `request_id`、枚举 `method`、固定 `route`、`http_status`、`duration_ms`、固定类别 `error_code`、布尔 `authorization_present`。

每个获准捕获的 MCP 请求在下游处理前立即写开始记录，后三个响应字段为 null。响应头就绪时以同一个 request-id 写终态，包括正常 200/202、认证/权限失败、异常及已分类 HTTP200 工具错误。流式正文不会被读取或等待。Authorization 布尔值不证明凭据格式或有效性。

截止时仍未得到响应头的请求写 `diagnostic_pending_at_cutoff`，HTTP 状态为 null，耗时截至窗口结束；这是一条明确的未完成快照，不是伪造的 HTTP 终态。后来返回的真实响应不再追加记录。每个在途请求拥有截止计时器，结束后取消；窗口空闲时，由下一次已有 `/api/health` 或 API 请求补写 CLOSED，协调流程在截止后主动读健康接口确保标记落盘。

另外预留三条控制记录，不代表真实 HTTP 请求：`diagnostic_window_opened`、`diagnostic_limit_reached`、`diagnostic_window_closed`。控制记录仍使用同样八字段，method=OTHER、HTTP/耗时=null、Authorization=false，以同一个窗口 UUID 区分于请求 UUID；不带其他请求路径/身份。健康请求只触发这些固定控制标记，本身不被当成 MCP 请求记录。

## 硬上限与可观察丢失

每 isolate 最多接纳 **1024 个请求**，接纳时各预留开始和终态两条。首次第1025个请求到达时写 LIMIT，之后不再捕获新请求，业务请求仍照常经过认证和处理；已接纳请求仍保留终态空间。LIMIT 与 OPEN/CLOSED 有独立预留，不能被请求记录占满。

最多 **2051 条应用记录，每条最多512 ASCII字节，合计1,050,112字节**（前缀、JSON和换行）。窗口结束后不会接纳新的请求记录，只允许已经预留的截止快照及 CLOSED。上限是单 isolate 的应用输出，不是混合日志文件大小或跨重启持久计数；运行时附加前缀不由本功能控制。不得通过重启刷新窗口或预算。

超过容量或单条编码/输出失败会尝试写独立预留的 LIMIT，并停止接纳后续请求记录；没有 OPEN、没有 CLOSED、出现 LIMIT、进程中途重启，或提取器报告截断，都不能称本轮完整捕获。日志后端失效无法靠同一后端保证标记，必须在通知用户前验证 OPEN 和无凭据探针对应的开始/终态；日志失败不会影响认证或业务响应。

## 流量依据

早先未采样样本有64请求，跨度1139.448秒，均值3.37次/分钟；峰值滚动一分钟7次，滚动十分钟34次。1024请求容量是该十分钟峰值约30倍；即使持续每分钟7次，十分钟70次也有约14.6倍余量。这只是历史样本，不能从当前采样日志精确推断当前总流量，也不能保证攻击/异常洪峰下不会触顶；LIMIT 是本轮不可完整使用的明确标志。

## 后续协调启用（本轮不开启）

1. 先确认用户可在指定时段操作，再约定明确 UTC FROM/UNTIL，最长十分钟。开始时间至少预留十分钟用于构建、上传、备份、切换和检查，不在用户等候期间抢先开启。
2. `deploy/vps/plan-mcp-capture.py` 默认只输出未武装计划，不连接服务器或修改文件。未来明确给它 `--source-commit`、`--from`、`--until` 后，它只校验并输出供构建使用的两个 define；仍不会构建、部署或开启生产。无时区、非完整SHA、过期/临近开始、倒序、超过十分钟均拒绝。
3. 用已核验代码SHA构建带这两个绝对时间的包，把窗口和限额写入 BUILD.json，核包hash；复用已验证且源码未变的web资产。部署脚本必须重新锁定现场旧版本，且在 FROM 之前至少留两分钟；若已错过余量则停止，重新协调时间，不能缩短用户操作窗口来赌时机。只按既有备份/原子切换流程短暂重启主服务，不动events/tunnel，不迁移数据。
4. FROM到达后读取既有 `/api/health` 触发OPEN，再做一次无凭据MCP探针，确认401且开始/终态同ID、无LIMIT，才由父任务通知用户在约定时段点一次。不要索取/读取真实Token或向第三方Agent发送测试请求。
5. 截止后读健康接口确保CLOSED，再用任务工作区只读提取器按FROM过滤：最多读2MiB、最多2304条，只输出八字段，任何截断均显式报告。检查每个开始ID对应真实终态或未完成快照，控制标记齐全且无LIMIT；相邻的200仍不能仅凭这些字段认定来自Today。
6. 绝对截止自动停止捕获。可用不带define的构建提前关闭，或按既有程序回滚目录回退；不恢复数据库，不改成员/凭据，不重启events/tunnel。既有混合 `service.log` 不截断或删除，临时八字段提取文件分析后可单独清理。
