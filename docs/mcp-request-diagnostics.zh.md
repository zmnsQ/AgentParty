# 临时 MCP 请求诊断

用途：客户端只能报告 `mcp.upstream_unavailable` 时，区分请求未到达、已到达未完成、认证/权限/协议拒绝，以及应用已返回响应。日志不能证明第三方客户端成功接收或使用了响应。

沿用应用 `console.warn` 输出和既有主服务日志，不启用全局 debug，不更改认证、Origin、代理或系统配置。普通构建默认关闭。仅在一次受控构建中显式定义 `__AGENTPARTY_MCP_DIAGNOSTICS_UNTIL__` 为绝对 UTC 到期时间；本次操作窗口为构建起两小时，发布记录保存准确期限。到期后即使服务重启也不会接纳新诊断请求。进行中的请求仍可输出完成记录。

只匹配 `/api/channels/:slug/mcp`，每个 isolate 最多接纳 64 个请求，合计最多 128 条记录（测试确认小于 50 KB）。重启/新 isolate 会重置数量，绝对期限不变；这是诊断流量上限，不是全实例持久计数。不要为延长窗口反复重启或重建。

固定前缀 `mcp_request_diagnostic` 后只含八个字段：`request_time`、服务端随机 `request_id`、枚举 `method`、固定路由模板 `route`、`http_status`、`duration_ms`、固定类别 `error_code`、布尔 `authorization_present`。开始记录后三个响应字段为 null；同一 ID 的完成记录表示响应头已就绪。流式响应不等待关闭，也不读取正文。HTTP 200 仍可伴随 JSON-RPC/工具错误类别；未经标记的错误仅按 HTTP 状态分类。

禁止记录实际群/用户/Agent 标识、客户端请求 ID、URL/查询参数、请求或响应正文、消息、Cookie、任何 header 值、Token/hash、异常对象或文本。这里只判断 Authorization header 是否存在，不能据此证明格式或凭据有效。日志输出失败不改变请求结果。

## 观察与退出

VPS 本次既有输出位置是 `/var/lib/agentparty-commons/logs/service.log`，不是应用 journal。用限定文件大小/尾部行数的只读提取，只解析上述固定前缀和字段；不输出混合日志其他内容。先用一次无凭据请求确认 401 与成对记录，再请用户重试一次并提供尝试时间。不要索取或复用真实 Token，不向 Today/其他 Agent 发起测试调用。

本功能不新建诊断文件、数据库、凭据或外部日志目的地。期限结束即停止新增；关闭编译 define 的正常构建或原子回滚到发布前目录可提前关闭。回滚不恢复数据库、不重启 events/tunnel。

到期不会删除已有混合日志；不得截断/删除 `service.log` 或其中无关条目。临时提取结果如需保存，只放本任务工作区且仍只含八字段；分析后删除该提取文件即可。混合生产日志继续遵循已有运维保留方式，单独清理须另行明确范围，不能声称此功能自动清除了历史记录。仓库测试覆盖默认关闭/过期、计数限制、成功/失败/异常、秘密 canary、开放流不被消费和日志失败不影响响应。
