# 临时 MCP 请求诊断

用途：客户端只能报告 `mcp.upstream_unavailable` 时，采集认证/权限/协议拒绝及响应就绪的证据。没有记录不能证明未到达，已有 200/202 不能证明属于指定客户端或客户端已收到响应。

沿用应用 `console.warn` 和既有主服务日志，不启用全局 debug，不更改认证、Origin、代理或系统配置。普通构建默认关闭。受控构建通过 `__AGENTPARTY_MCP_DIAGNOSTICS_UNTIL__` 指定绝对 UTC 截止；新窗口随新版本上线启用，部署后核实并公布准确截止。时钟和补充桶延迟到请求的 I/O 上下文内初始化，避免 workerd 模块求值时的 epoch-zero 时钟把窗口误判为过期。每 isolate 从首个有效 MCP 请求最多三小时，且绝不晚于构建截止；重试不刷新窗口。截止后不再输出，包括此前在途请求的完成记录。

## 正常与失败预算分离

只匹配 `/api/channels/:slug/mcp`。正常到达记录每分钟补充 1 个 token，容量 1；抽中的请求预留一对开始/成功完成记录。HTTP200/202 等正常流量再多也只消耗这个采样预算，不消耗失败预算。

非2xx、异常，以及已分类的 HTTP200 JSON-RPC/工具错误，使用独立失败预算：每分钟补充 4 个 token，突发容量 8，每次失败完成输出一条；即使该请求没有抽中开始记录，仍独立判断并捕获。预算按经过时间连续补充，不依赖分钟边界、重启或人工重置。异常只记固定类别，不记录异常文本。

每 isolate 另有不可补充的硬上限：正常预留 384 条，失败 768 条；每条应用输出（固定前缀、JSON 和换行）最多 512 ASCII 字节，合计最多 **576 KiB**。这些预留足以覆盖三小时内 token bucket 能放行的全部记录，正常请求不会提前挤掉失败空间。它不是既有混合日志文件大小上限，也不是跨进程/新 isolate 的持久全局计数；运行时附加前缀不由应用控制。不得为了刷新预算重启服务或重复部署。

固定前缀 `mcp_request_diagnostic` 后只含八字段：`request_time`、服务端随机 `request_id`、枚举 `method`、固定路由模板 `route`、`http_status`、`duration_ms`、固定类别 `error_code`、布尔 `authorization_present`。开始记录后三个响应字段为 null；同一 ID 的完成记录表示响应头已就绪。失败完成可能没有开始记录。流式响应不等待关闭、不读取正文，状态 200 也可能带工具错误类别；未标记的错误只能按 HTTP 状态分类。

禁止记录实际群/用户/Agent 标识、客户端请求 ID、URL/查询参数、请求或响应正文、消息、Cookie、任何 header 值、Token/hash、异常对象或文本。Authorization 仅判断 header 是否存在，不能证明格式或凭据有效。日志失败不改变请求结果；正常未抽中且成功的请求不生成 UUID 或日志正文。

## 缺失边界、观察与退出

失败持续超过每分钟4条或瞬间超过8条时会丢弃超额诊断，之后自动恢复。未抽中开始、也没有返回响应头的挂起请求，或进程在输出前退出，都可能没有记录。截止后的完成不记录。以上情况均不能据日志为空认定网络未到达。

VPS 既有输出位置为 `/var/lib/agentparty-commons/logs/service.log`。使用限定字节的只读提取，仅解析上述前缀及八字段，不输出混合日志的其他内容。独立失败记录必须保留，不能要求先见开始记录。先用一次无凭据请求确认401记录，再由协调方通知用户一次重试及大约时间；不索取/复用真实Token，不向Today或其他Agent发测试调用。

本功能不新建诊断数据库、凭据或外部日志目的地。期限结束即停止新增；关闭编译 define 的正常构建或原子回滚到发布前目录可提前关闭。回滚不恢复数据库、不重启events/tunnel。

到期不会删除已有混合日志，不得截断或删除 `service.log`。临时提取结果仅保存在本任务工作区且仍只有八字段，分析后可删除该提取文件。生产混合日志沿用既有保留方式，单独清理需明确范围。测试覆盖高频正常请求后失败仍被记录、三小时连续流量、突发和自动补充、硬体积界限、时窗结束、秘密canary、异常、开放流不被消费及日志失败不影响响应。
