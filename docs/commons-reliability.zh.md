审查日期：2026-10-21。基于 `01866a7ac816506f52518ea6b19fff8a5130595c`，保留该提交已经整合的租约隔离、撤销凭据清理、群组/账号切换隔离和发布前权限复核。

本轮使用独立分支 `fix/durable-receipts-export-20261021`，供合入 `feat/personal-agent-collaboration` 审阅。没有覆盖并行提交、修改主分支、部署生产资源或触发 GitHub Actions。

## 1. 修复了什么

### 延迟重试不再重复插入同一协作结果

此前，群消息只有十分钟的去重窗口。供应商结果已经发入群、但 D1 回执保存失败时，稍后重试可能再次插入消息。

现在以下三类**有效 UUID 操作键**在群组 DO SQLite 中保存持久回执：

- `cloud-run:<UUID>`：云端任务最终回答。
- `code-proposal:<UUID>`：代码提案通知。
- `code-published:<UUID>`：代码发布通知。

消息和回执在同一同步事务提交；回执写入失败会回滚本次消息及事务内副作用。回执绑定发送者的名称、类型、owner 和操作键，不只按显示昵称判断。

如果历史保留策略已经清理了消息正文，重试只确认原序号，不重建正文、不再次广播。对于升级前仍保留的旧消息，会在首次重试时补记回执。普通聊天键继续使用原来的窗口，不能把普通键误当成不可变操作 ID。

### 并发请求在真正写入前再检查一次

消息初次去重检查之后，还有异步 D1 权限/提及查询。两个请求可能都通过第一次检查。现在进入实际写入事务后、消费限额和创建投递副作用之前，会再次检查回执和消息，防止并发双写。

测试通过受控屏障，让两个请求都到达异步边界后再继续；同时验证普通键和持久协作键。

### 身份导出不会重复分页或漏掉回执

原 CLI 在某类数据导出结束后使用负游标，而服务端会把负数归零。其他集合仍在翻页时，已经结束的消息/审计集合就可能从第一页再次读取并被重复合并。

现在消息、审计、投递账本、协作回执分别维护游标。已结束的集合不重新合并；回执有独立 `receipt_after` 游标。遇到不前进的服务端游标会报错停止，不循环生成重复数据；旧服务端没有回执字段时也能结束。

回执导出不包含消息正文、附件或供应商凭据。按身份硬擦除会清除相应回执。

### 保留并复验已有租约保护

并行提交已经实现的云端/GitHub 租约所有权保护全部保留。本轮新增真实 Worker/D1/DO 路径上的故障注入回归，验证迟到的状态或错误不能覆盖接管者，撤销连接阻止结果回流，已保存的最终答案不会因为回执写失败而丢失。

“供应商完成、群消息已插入、D1 回执写入失败”之后，测试分别模拟一天后重试和消息正文已清理。恢复复用已保存答案及原序号，不重新调用付费供应商。

### 测试观察与范围

早先并行启动回环 HTTP 测试文件时，三个原有 Hermes 用例曾触发一秒超时；同一实现也有通过的运行。现将这两个契约测试文件串行执行，保留所有断言和超时测试，不增加生产超时、不增加付费请求重试。最终 Commons 入口已通过，但这些早期偶发超时的根因尚未完全确认。

故障注入用例会输出预期的 SQLite 约束错误，断言确认回滚后进程仍退出 0。Vite 仍提示既有主包超过 500 kB，不能据此宣称性能验收完成。

租约交接回归是在外部 HTTP 响应边界向实际 D1 注入后继租约/状态，消息并发测试使用受控并发请求。它们不是供应商真实账户验收，也不是多地区负载或真实进程断电测试。

## 3. 升级与数据保留

前序迁移 `0048_collaboration_lease_fencing.sql` 已在基线中，本次不重复新增同名迁移。升级较早版本时仍应先备份并迁移，再替换 Worker；旧请求需要排空，不能混用不检查租约/持久回执的旧代码来宣称同等保证。

DO 在启动时幂等创建回执表。每个已提交的协作消息增加一条小型元数据记录，不保存正文副本。普通历史清理不删除回执；身份硬擦除、群组销毁会结束相应保证。长期存储容量/配额管理仍需后续运维方案。

没有执行生产数据库迁移。本轮保留原 `LICENSE`、上游致谢、依赖 lockfile 和所有手动工作流。

## 4. 仍然不能宣称的保证

- 不是整个系统永久 exactly-once：远端供应商执行、WebSocket/外部 webhook 通知及其回执没有跨系统原子事务。
- 无法重建升级前已经被清理且从未留下回执的消息；不同发送者身份不是同一个去重主体。
- 不恢复从未成功提交的发布通知，也不撤销已经在途的远端 GitHub/供应商写入。
- 仍是手动同步，没有后台持久派发、预算调度或自动唤醒。
- 本次没有新完成 dot / Muse / Grok 品牌账户授权，也没有制作/签名/验收 macOS 或 Windows 安装包。

下一阶段仍应依次推进带预算与审批的持久任务调度、GitHub App / OAuth 授权、真实供应商账户联调，以及两平台原生安装与断网/休眠恢复验收。
