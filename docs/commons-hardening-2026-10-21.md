# Commons 并发与恢复加固记录

日期：2026-10-21。基于 `5e74a599309e2afb1ebbcd2eaf46f6a38f6f49d1` 的开发预览，继续修复云端 Agent 任务及 GitHub 发布的并发问题。这不是生产部署或所有供应商接入完成的声明。

## 本轮发现与修复

| 风险 | 实现 |
| --- | --- |
| 旧同步请求晚到，把新请求保存的完成状态或错误覆盖 | 每次启动、同步、取消使用独立 `lease_token`；结果、错误和回执更新按当前持有者校验 |
| 旧请求的 finally 释放新请求的锁 | 释放语句同时匹配任务/提案 ID 与本请求 token，不再只匹配 ID |
| 获取锁前的任务快照已经过期 | 获取锁后重新读取任务，再决定是否查询供应商或补发已保存的结果 |
| 断开连接后，飞行中的响应继续写入；撤销记录继续保存凭据副本 | 撤销、清除凭据密文、失效任务租约和撤销群组 Agent token 在 D1 batch 中完成；结果更新同时检查连接未撤销 |
| 供应商已完成，但群消息回执存储失败，把任务错误地降为 unknown | 已保存的终态不因后续投递错误回退；同步只补发保存的答案，不重新执行付费任务 |
| GitHub 发布的旧请求覆盖新发布回执或重复发送成功通知 | 状态更新与释放按发布租约持有者校验；只有成功保存发布回执的请求发送成功通知 |
| 旧的 proposed 快照在另一发布已变 unknown 后继续获批 | 获取发布租约时同时比对已读状态、digest、原租约 token 与期限；状态改变即要求重新读取 |
| 失去租约的发布者继续发起后续 GitHub 写入 | 每个写请求前检查并续期仍有效的发布租约；检查失败即停止，之前存在写入时保留不确定性 |

修改集中于 `worker/src/collaboration/{routes,proposals,github-changes}.ts`。原始 LICENSE、来源致谢、人工审批、专用提案分支及不覆盖主分支的规则保持不变。

### 回归测试的独立反证

保留新增测试及迁移，把三个生产源文件临时恢复到 `5e74a59`，仅运行新增 Worker 并发/存储场景：**11 项全部失败，退出码 1**；未选中的 21 项原有测试跳过。随后恢复修复代码，并重新执行完整检查。这说明回归测试确实能暴露修改前的状态覆盖、错误释放、撤销与回执恢复问题，不只是检查新增字段存在。

新增 4 项 GitHub loopback HTTP 契约另外验证：首次写入前失去权限时零写入；一次树写入后失去权限时不再创建提交/分支且结果不确定；权限检查异常不泄漏错误中的秘密；权限检查被暂停直到总超时后，不得继续发出写请求。

普通 Worker 集成测试仍通过 `SELF`。需要暂停外部响应或截取 D1 读写时序的新增测试直接调用真实 Worker handler，并保留真实本地 D1、Durable Objects、R2；只控制外部 HTTP 边界和指定的一次数据库故障。它们不是生产供应商账号测试，也不是多机器负载测试。

## 升级已有实例

新增列与新代码必须作为同一次维护升级处理。旧版本不知道 `lease_token`，所以不能让新旧写请求在同一数据库上混跑。

1. 暂停新任务、同步、取消与代码发布入口，停止并排空旧 Worker 的在途请求。备份数据库前按自己的安全策略处理其中的凭据与资料。
2. 应用 `0048_collaboration_lease_fencing.sql`：本地开发可用 `bun run --cwd worker migrate:local`；远端迁移只能对已确认属于自己的环境执行。
3. 切换全部实例到新代码，再恢复请求；先检查此前 unknown / publishing 任务，仍不盲目重发付费操作。

迁移保留原有任务和提案，新增列可为空；它会清空已撤销连接的凭据密文。清空当前数据库字段不代表旧备份、日志或供应商端凭据已经被擦除/吊销。不要把回滚旧程序当作安全回滚；需要回退时同样停止写入并重新评估。

## 仍然存在的边界与下一步

数据库所有权检查无法撤销已经发送的远端 HTTP 请求，也不能与 GitHub 的多个 REST 操作形成跨服务事务。未知发布结果仍须恢复同一提案。群消息仍使用上游约 **10 分钟**的去重窗口；本轮没有宣称永久 exactly-once 投递。

本轮没有实现后台持久调度或预算；没有完成 dot / Muse / Grok 的 OAuth、Events 和平台审核；Manus / Cue 仍只是消息投递；没有用真实 Hermes/Manus 账号或产品内的真实 GitHub 发布链路进行验收；没有编译、安装或签名 macOS / Windows 原生客户端；没有创建生产资源、执行远端数据库迁移、发布 Release 或合并主分支。

接下来的开发优先级：先建立真实供应商与测试仓库的端到端验收，再实现带去重 outbox 的后台调度及预算，随后推进 OAuth/事件接入和原生客户端安装测试。平台能力必须按实际授权与联调结果展示，不把通用 MCP 入口等同于品牌接入完成。
