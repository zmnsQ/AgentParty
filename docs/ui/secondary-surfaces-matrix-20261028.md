## Root cause / shared fixes required

1. `components/ModalPortal.tsx` renders into `document.body`, not under `.prototype-native-workspace`. Workspace-descendant skins cannot reach these dialogs. Do not fix by moving portals into clipping/stacking ancestors: preserve portal and focus isolation, give all application surfaces a shared root-level palette.
2. `styles/prototype-native-frame.css` defines `--pn-*`; secondary components still use `--t-*` / `--ac-*` / legacy `--d-*`. `styles/tokens.css:4–10` light/doodle theme sets `--ac-surface-3:#ffffff`, `--t-panel` to that surface and `--t-accent:#a95338`. This is the screenshot's white/orange path; not primarily literal white inside each dialog.
3. `styles/foundation.css:14–20`: `.d-card,.doodle-frame`, `.d-btn,.d-pill`, `.d-btn--primary` carry the old system into every nested component. Primary background is `var(--t-accent)`; changing only outer drawer does not fix descendants.
4. `styles/studio.css:115–122` explicitly restyles channel/sectioned/agentjoin/install dialogs with `--t-panel`, and selected section tabs with `--d-yellow`; `management.css` adds more layout/token consumers. `collaboration.css:21` has `.commons-primary` accent overrides with `!important`. Address these consumers rather than appending an indiscriminate dark background to everything.
5. `main.tsx` imports tokens → foundation → app → studio → management → workspace/mobile/chat → prototype layers. `App.tsx` separately imports native-frame. Component CSS imports add another cascade layer. Audit computed styles for both stored themes and portals, not just selector existence.
6. Keep semantic danger/warning/success colors distinct. Preserve existing theme preference IDs; do not silently force one theme to hide the discrepancy.
