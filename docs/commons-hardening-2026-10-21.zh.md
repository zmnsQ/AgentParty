## 已修复的问题

| 场景 | 原有风险 | 本轮改动 |
| --- | --- | --- |
| 同步、取消或恢复请求交错 | 旧响应覆盖新结果，旧请求释放新请求的租约 | 每次操作使用独立随机租约标识；保存结果、错误、回执和释放租约都检查当前所有者 |
| 读取状态与取得租约之间发生变化 | 使用加锁前的旧状态发起不必要的查询或取消 | 取得租约后重新读取任务，按当前状态决定操作 |
| 远端结果已完成，但保存群聊回执失败 | 把已完成任务降级为失败或未知，诱导重复付费操作 | 终态不被后续投递错误覆盖；保留答案，显式同步只恢复投递 |
| 连接在请求进行中被撤销 | 旧响应继续写入，已撤销连接长期保存可解密密文 | 在同一数据库批次撤销专用 token、清除租约和两份凭据密文；结果更新同时检查连接有效性 |
| GitHub 发布被新请求接管 | 旧错误覆盖新发布，重复宣布发布，失去权限仍继续 POST | 比较并更新发布状态及租约；每次远端写入前校验并续租；只有成功保存发布结果的请求发送通知 |
| 切换群组、账号或 API 客户端 | 旧数据、权限、草稿及未保存密钥在新上下文中短暂残留 | 整个协作子树按不含凭据的内部版本号重新创建；401/403 清除缓存视图 |
| 文件上传期间离开面板 | 上传返回后仍自动发起新的群聊投递 | 已开始的上传可以结束并保留文件，但不再开始后续自动投递 |

## 升级要求

新增迁移 [`0048_collaboration_lease_fencing.sql`](../worker/migrations/0048_collaboration_lease_fencing.sql)。
两个任务表增加可空的 `lease_token` 字段，并清理已撤销连接的凭据密文。
应用新服务代码之前必须先应用迁移。它不能通过只更新前端替代。

本地开发：停止旧服务 → 备份持久化数据 → `bun run --cwd worker migrate:local` → 启动新服务。
已部署环境：安排维护窗口，停止接收新的协作写操作并排空旧版本进行中的请求，
备份自己的数据库，在确认正确账户/环境后应用远端迁移，再部署新代码并恢复流量。
旧版本代码不会检查新的租约标识，因此本轮**不保证旧新版本混跑的并发安全**。
不要为回滚而删除租约字段或恢复已清除的连接密钥。
本轮没有执行任何生产迁移、创建云资源或部署。

撤销连接不等于撤销供应商 API key，不等于取消供应商已开始的任务；
需要时仍应去供应商端停任务、撤销密钥。
清理当前记录不是对数据库备份或请求内存进行可验证的安全擦除。

## 仍然存在的边界与下一步顺序

1. **可靠投递与成本控制。** 群聊最终投递仍受上游 10 分钟去重窗口限制；本轮不是永久 exactly-once。
   下一步应设计持久 outbox、退避重试、每群预算和紧急停用，再开放无人值守派发。
2. **真实账号接入。** Hermes 实际 API Server 联调，Manus/Cue 可靠回群，以及 dot / Muse / Grok 的授权、Events 与平台审核仍需分别验收。
   本轮没有索取或使用用户的供应商凭据，也没有新增真实供应商任务费用。
3. **桌面平台验收。** 本轮测试在 macOS 执行不等于原生客户端构建；没有编译 Rust、打包安装器、签名、公证或 Windows 实机测试。
4. **GitHub 应用链路。** 每次远端写入前的租约校验不能撤回已发出的 HTTP 请求，也不能将 D1 和 GitHub 多个 REST 操作变成一个原子事务。
   结果不确定时继续恢复同一不可变提案；不覆盖主分支，不强推，不自动合并。
   真实 GitHub App 权限、仓库 ruleset 与端到端发布仍需独立验收。

本轮未触发 GitHub Actions，未发布 Release，未修改原项目许可证。
