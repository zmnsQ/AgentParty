本轮修复开发预览中已复现的状态竞争，不增加供应商支持承诺。修改仅作用于协作服务、数据库迁移、回归测试及文档；上游 LICENSE、NOTICE、桌面标识、默认服务地址和手动构建工作流均未改动。

## 修复内容

| 问题 | 修复 | 对使用者的意义 |
| --- | --- | --- |
| 云任务租约只有到期时间，旧请求可覆盖新请求状态或释放新锁 | 每次请求使用随机 `lease_token`；保存结果、保存错误和释放租约均检查所有权 | 迟到响应不能再覆盖接手请求的状态，也不会以旧结果回群 |
| 同步/停止在加锁前读取状态，加锁后继续使用旧快照 | 成功获取租约后重新读取任务，调用供应商前再次验证所有权和连接有效性 | 避免按过时状态执行恢复操作 |
| GitHub 发布请求超时后，较旧成功/失败响应可能覆盖恢复发布 | 加锁比较原状态、摘要和租约；保存/释放均按所有者条件更新 | 已恢复的 PR 状态不会被旧请求改坏；只有保存成功的发布者发送群通知 |
| 已保存答案在写群消息回执失败后被标记成 `unknown` | 启动异常只更新仍处于活动状态的任务；完成态不回退 | 保留已完成答案，可重试回群，而不是重新执行付费任务 |
| 撤销连接仍保留加密凭据副本，且与结果保存存在竞争 | 在同一 D1 batch 中清除保存的凭据密文、撤销群 Agent token、作废租约；结果保存原子检查连接有效性 | 迟到的供应商结果不能重新写入已撤销连接的任务 |

`lease_token` 是内部并发所有权标识，不属于供应商凭据，也不出现在 API 响应中。它解决本服务的状态竞争，并不把外部 GitHub API、供应商或群消息存储变成一个跨服务事务。

## 升级与回滚注意事项

新增迁移：`worker/migrations/0048_collaboration_lease_fencing.sql`。

已有部署升级时，先暂停新的协作任务/发布入口并让旧请求结束，备份自己的数据库，**先应用迁移，再启用新服务代码**。本地仍可使用：

```sh
bun run --cwd worker migrate:local
```

远端迁移由部署管理员在自己的账户下执行，本轮未创建云资源、运行远端迁移或部署服务。不要让旧版本写入者与新版本长期混跑：旧写入者不检查新的所有权字段，会破坏保护条件。回滚旧代码也会重新引入已修复问题，不能把删除新列作为常规回滚操作。

迁移为两个表添加可空 `lease_token`，不改变既有租约到期时间，并清除历史上已撤销连接保存的两类凭据密文。连接/任务审计记录以及已保存的历史答案保留。撤销不会恢复这些凭据，应以新连接 ID 重新授权。

## 明确保留的边界与下一阶段

- 撤销的是 Commons 的连接及群访问权，并非供应商账户上的 API key，也不是对远端任务已停止的确认。已发出的请求可能仍在远端执行；已经授权/投递的消息无法被撤销操作追回。数据库备份中的历史凭据副本需由部署者按保留策略处理。
- 群消息最终投递仍受上游 **10 分钟去重窗口**约束。崩溃发生在群消息已保存而回执未持久化之间、再在窗口外重试时仍可能重复；本轮不宣称永久 exactly-once。
- 只有本服务的状态保存被租约所有权约束。GitHub 专用分支和完整树验证仍负责外部发布恢复；没有跨服务原子锁，也没有主分支 force push 或自动合并。
- 尚未完成：dot/Muse/Grok 的账号侧授权与完整联调、OAuth/MCP Events、后台持久派发与预算控制、真实 Hermes/Manus 账户验收、macOS/Windows 原生编译/安装/签名验收。此次在 Mac 上跑 TypeScript/Worker/Web 测试不等于完成原生桌面验收。
- 没有触发 GitHub Actions、发布 Release、部署生产服务或替用户开通付费资源。

下一阶段优先把授权和单群事件回调形成可验收闭环，再加入具有预算上限和停止开关的后台派发；原生客户端应另设 macOS 与 Windows 的独立验收，不以网页构建代替。
