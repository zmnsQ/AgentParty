# OAuth 授权确认过期／会话变更的安全恢复

Agent Commons 作者：zmnsQ；基于郭立（Guo Li / leeguoo）及贡献者的 AgentParty 二次开发，保留原 LICENSE。

## 问题范围与证据

2026-10-22 用户反馈 `/oauth/authorize` 返回 `invalid_or_expired_consent`。这个错误原来混合了确认单过期、登录会话发生变化、已经使用或无法匹配的确认单等情况；**不能仅凭截图断定该用户本次是其中哪一种，更不能据此指责用户超时或操作错误**。

在隔离数据库中使用与线上相同版本的 Wrangler 4.147.0 / D1 和真实生产 OAuth handler 复现：

- 新生成、当前会话内的确认单可以完成 302 回跳以及 200 授权码兑换。
- 将合法确认单设为过期，原代码返回同一个 `invalid_or_expired_consent`。
- 同一账号切换为新的已验证浏览器会话后提交旧表单，原代码也返回相同错误。
- 原逻辑先删除确认单，再保存授权码。若保存失败，就会提前消耗唯一确认记录，重试无法恢复。

本次没有读取用户真实 Cookie、验证码、密钥或已授权私人内容，也没有代替用户点击实际 ChatGPT 的授权确认。真实用户的最终绑定结果仍须由客户端回跳确认。

## 修改

1. 保留十分钟确认期限、严格 Origin、登录、本站 MFA、群主与群策略、client/redirect/resource 及 PKCE 校验。
2. 对**正确的一次性 nonce + 同一个当前已登录账号**，若原表单过期或会话已变化，只返回 303 到本站**新的同意页**，生成新 request ID 和 nonce。原确认作废，不发授权码。用户必须重新确认清楚显示的群和权限。
3. 恢复用的 client、redirect、state、resource、scope 与 challenge 只取自经过匹配的服务器记录；不接受表单提供的替换值。客户端侧 OAuth 流程也过期时，仍需回到 ChatGPT 重新连接。
4. 使用 D1 原子 batch 同时保存授权码并消耗一次性确认。插入失败时回滚，合法确认记录仍可重试。两个并发提交最多签发一个授权码。
5. 对错误 nonce、不同账号、失效客户端或关闭的群策略仍拒绝，不进入恢复流程。已使用或缺失记录依然不能重放；浏览器看到中英可读的恢复说明，不再只看到 JSON 错误。

没有放行空 Origin，没有取消 MFA，没有延长旧 nonce 的有效期，没有让旧批准自动迁移到新会话。没有数据库迁移或凭据轮换。

## 完整浏览器验证

隔离 Chrome 的原生 HTML 表单，加载真实生产 Hono OAuth handlers；D1 使用临时测试数据库，只包含合成账号和凭据。外部回调在本地被测试程序截获，未联系用户的真实 ChatGPT/GitHub 账号。

| 情况 | 首次点击 | 再次确认后 |
|---|---|---|
| 全新表单 | 正常返回一次性 code | code + S256 PKCE 兑换 HTTP 200 |
| 合法但过期的表单 | 返回新确认页；旧确认没有生成 code | 新确认 + code 兑换 HTTP 200 |
| 同账号的新会话提交旧表单 | 返回新确认页；不转移原批准 | 新会话明确批准后兑换 HTTP 200 |

记录：`docs/validation/oauth-consent-recovery-2026-10-22.json`。

新增回归覆盖：过期刷新、同账号会话切换、错误 nonce、其他账号、策略关闭、保存失败回滚、并发提交及已使用确认的本地化提示。DCR 测试使用各自的合成客户端 IP 以避免互相污染；生产限流未放宽。

用户重试必须从 ChatGPT 插件重新点击连接。若这期间确认页过期或同账号重新登录，服务端会展示新确认页并要求再确认，不能直接把之前的批准当作新授权。
